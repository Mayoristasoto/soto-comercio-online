# Architecture rules

- Apply punctuality type filters and ordering through a pure projection shared by the table, employee detail and PDF inputs so exports match the selected incidents without changing stored records.

- Keep pause report pairing and summaries in a shared pure module used by the Fichero view and exports, so on-screen and downloaded durations agree.
- Pause reports are read-only analyses of clock records, not generators of disciplinary incidents; display recorded justifications separately from observed durations.
- Derive break concurrency with exact half-open UTC intervals, split at Argentina day boundaries and grouped by assigned branch; use the same pure analysis in heatmaps and exports to avoid contradictory overlaps, and never infer incomplete breaks.
- Daily break timelines and their browser-generated PDFs consume the shared concurrency segments, preserving selected branch/day and employee coincidence context without publishing employee reports as static public assets.
- Horario 2 schedules live in h2_* tables; state transitions (send, approve, return, publish, new version, copy, template) go only through SECURITY DEFINER h2_* RPCs, and the latest published version wins over fixed shifts when resolving a day's schedule, so the kiosk and lateness checks follow what RRHH published.
- Horario 2 validations and coverage are computed in the pure module src/lib/horario2.ts shared by grid and panels, so warnings and coverage agree.
- Horario 2 drag-and-drop moves the existing shift within its branch plan through the same RLS-protected update as the editor, preserving schedule fields and using the shared pure validation before saving, so moves do not bypass planning restrictions. Ctrl+click selects multiple shifts and dragging any selected one moves them all together via the pure prepararMovimientoMultiple projection, preserving relative offsets.
- Removing an imported approved Horario 2 shift uses the RRHH-only SECURITY DEFINER RPC to atomically create a draft excluding that shift and preserve the approved original; never widen direct delete policies for approved plans.
- Consecutive-day extensions project daily copies through the shared shift validations and persist the source plus copies in one RLS-protected upsert, so failures cannot leave partial extensions or overwrite destination shifts.
- Retroactive incident recalculation is a read-only preview RPC classified by the pure module src/lib/recalculoIncidencias.ts; changes reach fichajes_tardios/pausas/cruces rojas only through the RRHH-only atomic apply RPC, which annuls (never deletes) and logs every applied/discarded row.
- Telegram access is a per-person whitelist: the telegram-anotaciones webhook checks the Telegram secret header, then looks up the sender's chat_id in telegram_autorizados (chat_id → empleado_id plus one flag per command group) and refuses anyone missing or inactive after recording them in telegram_solicitudes for RRHH to review. Notes are inserted into empleados_anotaciones with creado_por = the writer's employee row, never a fixed author, and each command is gated by its own flag through the pure module supabase/functions/_shared/telegramAccesos.ts (shared with the app); only puede_administrar allows /permitir, /quitar and /autorizados.
- Personal agenda reminders live in agenda_personal (RLS: own employee only); Telegram free text is parsed by AI in the telegram-anotaciones webhook and a per-minute cron call (?cron=1) sends due reminders once, marking avisado and delivering each reminder to its own author's authorized chat, falling back to the configured RRHH chat.
